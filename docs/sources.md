# Source research

| Source | Observed structure and role |
| --- | --- |
| [Arm Keil CMSIS index](https://www.keil.com/pack/index.pidx) | XML `pindex/pdsc` rows provide publisher, package, version and base URL. The release in the PDSC must match the advertised version. |
| [Keil STM32F4xx_DFP](https://www.keil.arm.com/packs/stm32f4xx_dfp-keil/overview/) and [STM32F1xx_DFP](https://www.keil.com/pack/Keil.STM32F1xx_DFP.pdsc) | F4 `3.1.1` lists STM32F407VE and STM32F407VG, inherits RM0090 from STM32F407 and includes variant patterns such as `STM32F407VETx`. F1 `2.4.1` lists STM32F103C8 with local pack-relative book references. Inheritance follows the [PDSC family specification](https://open-cmsis-pack.github.io/Open-CMSIS-Pack-Spec/main/html/pdsc_family_pg.html). A wildcard is insufficient proof of an orderable part. |
| [ST STM32F407VE](https://www.st.com/en/microcontrollers-microprocessors/stm32f407ve.html), [STM32F407VG](https://www.st.com/en/microcontrollers-microprocessors/stm32f407vg.html), [STM32F103C8](https://www.st.com/en/microcontrollers-microprocessors/stm32f103c8.html) | Product tables identify exact order codes. The official eStore product listing has stable, separate rows in the observed captures, with an explicit datasheet link per SKU. Captures confirmed VET6, VET6TR, VGT6 and C8T6 on the intended base devices. |
| [ST STM32F407/417 documentation](https://www.st.com/en/microcontrollers-microprocessors/stm32f407-417/documentation.html) and [STM32F103 documentation](https://www.st.com/en/microcontrollers-microprocessors/stm32f103/documentation.html) | The catalogs include documents for multiple subfamilies. F407 VE and VG share DS8626 rev 12, ES0182 rev 19 and RM0090 rev 22. F103 C8 is in the x8 medium-density group covered by DS5319 rev 20, ES096 rev 15 and RM0008 rev 21. Those files have separate device-level associations in the catalog, and their source coverage is recorded as subfamily. |
| [ST open pin data](https://github.com/STMicroelectronics/STM32_open_pin_data) | Official machine-readable pin data, for example `STM32F407V(E-G)Tx.xml`, uses part patterns. It does not establish the exact commercial suffix, document set or revision metadata needed here. |
| [Microchip Product Data API](https://www.microchip.com/designresources/PartnerDataExchange/ProductAPI-user-guide.html) | A public `part=pic10f202` probe returned HTTP 200 with multiple orderable parts, base part fields and datasheet URLs. This API is a candidate for v0.2. |

## Access and review

The ST product and documentation endpoints returned HTTP 567 from this environment. The official eStore returned HTML for all three target device listings. [ST website terms](https://www.st.com/content/st_com/en/about/terms-of-use.html) restrict automated access. The ST Adapter uses reviewed local evidence, and the scheduled collector does not connect to ST websites. The [ST eStore robots.txt](https://estore.st.com/robots.txt) did not disallow the observed paths, but robots rules do not grant permission to automate access.

The CMSIS collector checks robots.txt before reading each origin, including download redirects. Keil returned 404 for robots.txt. Its Azure Blob distribution hosts returned 400 for the root-level path outside any container. These responses indicate missing policies. Explicit denials, rate limits and an unreachable robots endpoint stop collection. Requests use an identifying user agent, run sequentially with a one-second minimum gap, have a 20-second timeout per HTTP request and retry transient failures once. The collector deduplicates identical requests within a run and retains the last accepted observation time when pack evidence is unchanged.

To update ST evidence, review each product listing and document through an allowed channel. Save the official eStore markup locally as `st-store-<base-model-lowercase>.html` for each of the three scoped devices. Review the document version and applicability against the PDF title or supported-device table, update `data/seeds/st-documents.json` and its review timestamp, then run `pnpm import:st <dir> <UTC ISO observation time>`. Run validation and open a PR. Product extracts and curated document evidence are separately timestamped. ST document dates were omitted where only an update label or a month was established. The family documentation page or eStore may use a different official URL alias than the product page or the PDSC. These aliases are tracked as evidence without inventing URL equivalence or revision dates.

## Test extracts

`data/fixtures/keil-index.pidx` contains the two Keil index rows. `keil-f1.pdsc` and `keil-f4.pdsc` retain the relevant release, device levels and book records from the official descriptors. The F4 descriptor is published by [Open-CMSIS-Pack](https://github.com/Open-CMSIS-Pack/STM32F4xx_DFP). `st-store-*.html` retains minimal row structure, observed part numbers and official link attributes from the eStore URLs declared in `collector/scope.ts`. The test suite runs offline.
